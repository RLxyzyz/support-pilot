## 一、已完成的改动（历史补录）

### 1. 后端 RAG 从关键词匹配升级为 Milvus 真实向量检索
- **时间**：前几轮迭代
- **背景**：原 RAG 仅基于 `kb_doc` 元数据做关键词轻量匹配，召回质量差。
- **改动内容**：
  - `pom.xml`：引入 `spring-ai-starter-vector-store-milvus`（Spring AI 1.0.0），embedding 走 OpenAI 兼容客户端。
  - 新增 `DashScopeEmbeddingModel`：用 JDK `HttpClient` 直调百炼 `/compatible-mode/v1/embeddings`，`@Primary` 覆盖 Spring AI 自动配置的 `OpenAiEmbeddingModel`（后者调百炼返回 404 且吞响应体）。
  - 新增 `KbIndexService`：文档导入（切分 → 写 `kb_chunk` → embedding → 写 Milvus）、`rebuild()` 全量重建、`search()` 相似度检索。
  - `RealRagService`：优先 Milvus 相似度检索（topK=5，阈值 0.3），向量库不可用时回退关键词匹配。
  - `application.yml`：配置 embedding（base-url / model / dimensions）与 Milvus 连接；`application-secret.yml`（gitignored）填 embedding key。
- **关键约束（勿动）**：embedding base-url 必须是工作空间专属域名 + `/compatible-mode/v1`，不能是 `/api/v1`；key 必须属于该工作空间。
- **状态**：已调通，用户确认「成功了」。

### 2. 修复「采纳 AI 回复后看不到回复内容」
- **时间**：上一轮
- **根因**：`AgentService` 生成的回复只通过 SSE 推前端，从不写库；`DraftService.approve()` 只改状态为「已解决」，既不存草稿内容也不创建会话消息；前端 `adopt()` 只传 draftId 不传正文。数据库验证：4 条已采纳草稿 `content` 全为 NULL，其中工单 #41252 采纳后 `ticket_message` 为 0 条。
- **改动内容**：
  - `DraftService.approve()`：接收回复内容，作为一条**对客户可见**的消息写入 `ticket_message`（who=当前用户、role=管理员/工程师、internal=false），同时把内容落库到 `draft.content`，再置「已解决」。
  - `DraftController.approve()`：放行请求体里的 `content`。
  - 前端 `client.ts`：`approveDraft` 增加 `content` 参数并随请求提交。
  - 前端 `AIPanel.adopt()`：把用户最终确认（可能编辑过）的草稿内容传给后端，空内容时拦截。
- **状态**：`mvn compile` 与 `tsc --noEmit` 均通过；**等用户在 IDEA 重启后端后做端到端复测**。
- **遗留**：历史 4 条已采纳草稿的回复内容当时未存库，无法回填；修复后新采纳都会留存。

### 3. 已解决工单内容同步进向量库
- **时间**：上一轮
- **背景**：知识库数据仅来自手动上传，AI 无法引用历史已解决工单。
- **改动内容**：
  - `KbIndexService`：抽取 `persistDocument` 公共方法；新增 `ingestTicket(Ticket)` 构建工单全文（标题/元信息/问题描述/对外会话与解决方案，**内部备注不入库**）并向量化；以 `path=ticket/#{id}` 幂等去重。
  - `toDocument` 写入 metadata：`chunk_id` / `doc_id` / `doc_name` / `doc_path` / `product_line`。
  - `KbService`：新增 `ingestTicket(Long)`、`syncResolvedTickets()`（批量同步所有已解决工单，幂等可重复执行）、`ingestTicketAsync(Long)`（事务提交后虚拟线程异步，失败不影响主流程）。
  - `KbController`：新增 `POST /api/kb/sync-resolved-tickets`。
  - `DraftService.approve()` 与 `TicketService.updateStatus()` 置「已解决」时触发 `kbService.ingestTicketAsync` 自动入库。
  - 前端 `client.ts` + `KnowledgeBase.tsx`：增加「同步已解决工单」按钮。
  - 仓储：`KbDocRepository.existsByPath`、`TicketRepository.findByStatus`。
- **状态**：`mvn compile` 与 `tsc --noEmit` 均通过；**等用户在 IDEA 重启后端后做端到端复测**（首次调用返回了 `No static resource`，因运行中 JVM 未加载新端点）。

### 3. 后端实现（贴合现有分层约定：entity / repository / service / controller / dto / common）

   - `UserController`：create / update / delete（实施时把 update 也纳入了）
